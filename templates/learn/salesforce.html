Module 1: Salesforce Core Architecture & Fundamentals

Explain Like I'm 10: The Lemonade Stand CRM Story

Imagine you run a front-yard lemonade stand with 3 customers. You can easily remember that neighbor Bob likes extra sugar, Alice prefers crushed ice, and Charlie only visits on Tuesdays.

Now imagine your lemonade stand expands into 10,000 stands worldwide with millions of customers. You cannot keep all those preferences on sticky notes! You need a secure, collaborative digital brain that your entire company can open on any phone or laptop to instantly know each customer's favorite recipe, purchase history, and complaints.

CRM stands for Customer Relationship Management. And Salesforce is the most widely adopted enterprise CRM cloud on earth.

1. The Multi-Tenant Cloud & The Apartment Building Analogy

In traditional on-premise software, every company bought their own private physical server. In Salesforce's Multi-Tenant Cloud, thousands of companies share the same underlying servers, database storage, and compute hardware—just like 100 families living inside a luxury apartment building.

Tenant Isolation (Private Keys)

Each customer's data is strictly partitioned using an Organization ID (Org ID). Company A can never query or view Company B's records, even though they reside on the same database cluster.

Governor Limits (The Water Meter)

To prevent one apartment from hogging all the water and lowering pressure for everyone else, the runtime engine enforces strict governor limits on CPU time, memory heap, and database queries.

2. Metadata-Driven Architecture

In Salesforce, your business logic, page layouts, validation rules, custom fields, and code are stored as Metadata (structured XML definitions). Your actual business rows (customer names, phone numbers) are stored as Data.
This clean separation is why Salesforce can automatically push seasonal platform updates (Spring, Summer, Winter) three times every year without breaking your custom applications!

3. Summary Table of Critical Governor Limits

Module 2: Salesforce Administrator Deep-Dive

Salesforce Administration is the foundational backbone of every implementation. An effective administrator designs the data model, configures enterprise security, and builds declarative automations without writing code.

1. The 4-Layer Security & Access Model

The Medieval Castle Analogy

Layer 1 (The Drawbridge): Login IP ranges and business hours.
Layer 2 (Your Job Title): Profiles & Permission Sets dictate whether you're allowed in the kitchen (Recipes/Accounts) or armory (Invoices).
Layer 3 (The Default Lock): Organization-Wide Defaults (OWD) lock records by default.
Layer 4 (The Keys): Role Hierarchy & Sharing Rules grant exceptions to teammates and managers.

Profiles vs. Permission Sets
  • Profile: A user's baseline. A user can have only one profile. Controls default Record Types, Page Layout assignments, and login IP hours.
  • Permission Sets: Modular permissions layered on top of profiles. A user can have many permission sets.
  • Permission Set Groups: Bundles multiple permission sets together into a single assignment based on job function.
  • Salesforce Modern Trend: Salesforce is phasing out permissions on profiles. Best practice is giving users a minimal baseline profile and granting all CRED permissions via Permission Sets!
Record-Level Sharing Mechanisms
  • Organization-Wide Defaults (OWD): The most restrictive baseline: Private, Public Read Only, Public Read/Write, or Controlled by Parent.
  • Role Hierarchy: Automatically rolls record visibility vertically upward to managers (if "Grant Access Using Hierarchies" is checked).
  • Sharing Rules: Horizontally opens access to public groups or roles based on criteria (e.g., "State == California") or ownership.
  • Manual Sharing & Apex Sharing: One-off grants to specific users or teams via the standard Share button or Object__Share table.

2. Data Modeling & Relationships

3. Declarative Automations: Salesforce Flows

Legacy Workflow Rules and Process Builder are officially retired. Salesforce Flow is now the unified automation engine:

Screen Flows

Step-by-step interactive UI forms guiding customer service reps or sales teams through structured data capture.

Record-Triggered Flows

Executes on record create, update, or delete. Before-Save for fast same-record field updates; After-Save for cross-object updates, emails, and external callouts.

Flow Orchestrator

Orchestrates complex multi-user, multi-department enterprise workflows with asynchronous milestones and approvals.

Module 3: Programmatic Apex Developer In-Depth

Apex is Salesforce's proprietary object-oriented, strongly typed programming language executed natively on the multitenant server runtime.

1. Collections & SOQL Relationship Queries

Never query single records. Always use Collections (List, Set, Map) to bulkify:

// Query Parent Account fields AND Child Contacts in one query (Parent-to-Child Subquery) List<Account> accounts = [ SELECT Id, Name, Industry, (SELECT Id, FirstName, LastName, Email FROM Contacts WHERE Email != null) FROM Account WHERE AnnualRevenue > 1000000 LIMIT 100 ]; // Build an instant lookup Map indexed by Account Id Map<Id, Account> accountMap = new Map<Id, Account>(accounts);

2. The Trigger Handler Framework Pattern

Rule: Keep triggers logic-free! Dedicate one trigger per object that delegates immediately to a testable Handler class:

// File: OpportunityTrigger.trigger trigger OpportunityTrigger on Opportunity ( before insert, before update, after insert, after update ) { OpportunityTriggerHandler handler = new OpportunityTriggerHandler(); if (Trigger.isBefore && Trigger.isInsert) { handler.onBeforeInsert(Trigger.new); } else if (Trigger.isAfter && Trigger.isUpdate) { handler.onAfterUpdate(Trigger.new, Trigger.oldMap); } }

3. Asynchronous Apex Comparison

Type Interface / Signature Key Advantage Limitations
@future @future(callout=true) static void myMethod(...) Easy to write; avoids Mixed DML errors; executes third-party HTTP callouts. Only accepts primitive parameters; cannot be monitored or chained.
Batch Apex implements Database.Batchable<sObject> Processes up to 50 million records broken into batches of 200. Each batch gets fresh limits. Only 5 concurrent batch jobs can run at once in an org.
Queueable Apex implements System.Queueable Accepts complex sObjects; returns an AsyncApexJob Id; allows job chaining. Only 1 child job can be chained per execution in developer editions.
Schedulable Apex implements System.Schedulable Executes on a precise recurring schedule via Cron expressions. Limited to 100 scheduled jobs at any given time.

4. Unit Testing & Test Data Factories

Production deployments require at least 75% code coverage across all Apex triggers and classes, and all tests must pass with zero failures:

@isTest private class OpportunityTriggerTest { @testSetup static void setupData() { Account testAcc = new Account(Name = 'Acme Corp'); insert testAcc; } @isTest static void testOpportunityStageDiscount() { Account acc = [SELECT Id FROM Account LIMIT 1]; Test.startTest(); // Resets governor limits for the test Opportunity opp = new Opportunity( Name = 'Cloud Contract', StageName = 'Prospecting', CloseDate = Date.today().addDays(30), AccountId = acc.Id ); insert opp; Test.stopTest(); // Forces all asynchronous queueable jobs to complete Opportunity result = [SELECT StageName FROM Opportunity WHERE Id = :opp.Id]; Assert.areEqual('Prospecting', result.StageName, 'Stage should match initial insert'); } }

Module 4: Lightning Web Components (LWC) Modern Frontend

Lightning Web Components (LWC) is built directly on W3C standard Web Components (Custom Elements, Shadow DOM, ES6+ Modules, and CSS variables), delivering high performance with minimal framework overhead.

1. Component Bundle Structure

myComponent.html

Template markup using declarative directives like lwc:if, lwc:else, and for:each.

myComponent.js

JavaScript controller class extending LightningElement to manage state and user events.

myComponent.css

Encapsulated styles scoped strictly to this component via Shadow DOM boundaries.

myComponent.js-meta.xml

Configuration file declaring where the component can live (e.g. lightning__RecordPage).

2. Core Decorators & Wiring Apex

import { LightningElement, api, wire, track } from 'lwc'; import getRecentCases from '@salesforce/apex/CaseController.getRecentCases'; export default class AccountCasesViewer extends LightningElement { @api recordId; // Injected automatically on a Record Page @track searchFilter = ''; // Reactive @wire adapter: automatically refetches when recordId or searchFilter updates @wire(getRecentCases, { accountId: '$recordId', filterText: '$searchFilter' }) casesList; handleFilterChange(event) { this.searchFilter = event.target.value; } }

3. Component Communication Patterns

Pattern Mechanism Description
Parent → Child Public @api property or method Parent sets a property on child tag: <c-child-item user-id={userId}></c-child-item>.
Child → Parent Custom Events (dispatchEvent) Child dispatches event: this.dispatchEvent(new CustomEvent('select', { detail: id })). Parent listens with onselect={handleSelect}.
Unrelated Components Lightning Message Service (LMS) Publish/subscribe bus across Visualforce, Aura, LWC, and Utility Bars using publish(this.messageContext, RECORD_SELECTED_CHANNEL, payload).

Module 5: Enterprise Integration Architecture

Enterprises connect Salesforce with ERPs (SAP, Oracle), payment gateways (Stripe), and modern data lakes. Salesforce supports both inbound (external systems calling in) and outbound (Salesforce calling external endpoints) integration patterns.

1. Integration Classification Patterns

Request-Response (Real-Time REST)

Synchronous callouts via HTTP GET/POST/PUT/DELETE. Ideal for credit card authorizations, immediate address verification, or retrieving real-time stock inventory.

Event-Driven Pub/Sub (Platform Events)

Asynchronous pub/sub architecture built on Kafka/CometD. Salesforce publishes events when opportunities close, and downstream enterprise middleware subscribes instantly.

High-Volume Bulk Synchronization

Bulk API 2.0. Optimized for loading or extracting millions of records in asynchronous background batches without exhausting API limits.

Change Data Capture (CDC)

Salesforce automatically publishes near-real-time event streams whenever any standard or custom record is created, modified, or soft-deleted.

2. Named Credentials & External Credentials (Best Practice)

Security Requirement: Never hardcode endpoint URLs, client IDs, or OAuth bearer tokens in Apex code! Use Named Credentials which store authentication details securely inside Salesforce setup:

// Clean Outbound Callout using a Named Credential! Http http = new Http(); HttpRequest request = new HttpRequest(); // 'callout:Stripe_Gateway' references the Named Credential securely request.setEndpoint('callout:Stripe_Gateway/v1/charges'); request.setMethod('POST'); request.setHeader('Content-Type', 'application/json'); request.setBody(JSON.serialize(new Map<String, Object>{ 'amount' => 5000, 'currency' => 'usd' })); HttpResponse response = http.send(request); if (response.getStatusCode() == 200) { Map<String, Object> result = (Map<String, Object>) JSON.deserializeUntyped(response.getBody()); System.debug('Charge Id: ' + result.get('id')); }

Module 6: Developer Tools, Data Loaders & CI/CD Pipelines

Modern Salesforce development has evolved from manual changesets in production to mature, Git-driven CI/CD DevOps workflows.

1. Essential Workstation & IDE Setup

Visual Studio Code + Salesforce Extension Pack

The official standard IDE for Salesforce development. Includes syntax coloring, auto-completion, SOQL builder, and test execution runners.

Key VS Code Extensions:
  • Apex PMD: Real-time static analysis identifying governor limit violations, SOQL in loops, and security bugs.
  • Prettier & ESLint: Formats HTML, CSS, and enforces modern JavaScript rules.
  • GitLens: Tracks line-by-line commit authorship and branch comparisons.
Salesforce CLI (sf commands)

Command-line powerhouse for authenticating orgs, deploying metadata, and managing scratch orgs:

# Authenticate a developer org sf org login web --alias DevHub # Deploy source code to target org sf project deploy start --target-org staging # Run all unit tests with code coverage report sf apex run test --code-coverage --result-format human

2. Data Management Tools

Data Loader

Official client application supporting Insert, Update, Upsert, Delete, and Export for up to 5,000,000 records. Supports both interactive GUI mode and headless automated CLI batch jobs.

Salesforce Inspector Reloaded

Indispensable Chrome/Firefox browser extension. Inspects record metadata instantly, tests rapid SOQL queries, and exports raw JSON/CSV directly from any record page.

Data Import Wizard

Native browser-based admin wizard for importing up to 50,000 records with built-in deduplication for Accounts, Contacts, and Leads.

3. Ant Migration Tool vs. Modern CI/CD Pipelines

Ant Migration Tool (Legacy Apache Ant)

Java-based command-line utility driven by build.xml and package.xml metadata manifests. Historically used to script deployments between sandbox and production.

<target name="deployProd"> <sf:deploy username="${sf.user}" password="${sf.pass}" serverurl="https://login.salesforce.com" deployRoot="src" /> </target>

State-of-the-art automated DevOps utilizing Salesforce CLI and sfdx-git-delta (SGD) to deploy only changed files:

  3. Merged to Main: Automatically deploys incremental delta package to UAT and Production.

Module 7: Agentforce — Autonomous Enterprise AI Agents

Explain Like I'm 10: From Calculators to Smart Autonomous Robots

In the past, automated chatbots were like vending machines: you pressed button B-4, and it dropped a soda. If you asked a vending machine "Can you check if my order was delivered while I was away?", it had no idea what you meant.

Agentforce is completely different. It is an autonomous AI agent with a brain. You give it a mission, rules, and access to your business tools. It listens to customers, reasons through steps, looks up data in real time, and executes actions across your company automatically 24/7—safely guarded by enterprise security.

1. The Atlas Reasoning Engine

At the heart of Agentforce is the Atlas Reasoning Engine. Unlike simple LLMs that immediately generate text, Atlas follows a continuous reasoning loop:

1. Understand

Interprets customer intent and evaluates business context.

2. Ground

Retrieves real CRM records, policies, and Data Cloud embeddings.

3. Plan

Determines which sequential actions or Flows must execute.

4. Execute

Invokes Apex methods, sends emails, or escalates to humans.

2. The 4 Architecture Pillars of an Agent

Pillar Function Example Configuration
Role & Guidelines Natural language prompt defining identity, company tone, and boundaries. "You are Coral, an expert technical support specialist for Alpine Outfitters. Always remain polite and professional."
Topics Subject areas the agent knows how to discuss and handle. "Order Inquiries", "Warranty Replacements", "Account Password Resets".
Actions Executable tools the agent calls to inspect or mutate data. Invocable Apex classes, Auto-launched Flows, Prompt Templates, or MuleSoft APIs.
Grounding with Data Cloud Feeds structured enterprise data and vector PDF embeddings to eliminate hallucinations. Product manual PDFs, past service case history, and real-time shipping carrier API status.

3. How Developers Build Custom Agent Actions in Apex

To expose a capability to an Agentforce agent, write an Apex method annotated with @InvocableMethod. Describe what the method does in plain English so the Atlas Reasoning Engine knows when to choose it:

public with sharing class OrderAgentService { @InvocableMethod( label='Check Order Status' description='Returns the real-time shipping carrier tracking status and expected delivery date for an order number' ) public static List<OrderStatusResult> getOrderStatus(List<OrderStatusRequest> requests) { List<OrderStatusResult> results = new List<OrderStatusResult>(); for (OrderStatusRequest req : requests) { OrderStatusResult res = new OrderStatusResult(); Order ord = [SELECT Status, Tracking_Number__c, Delivery_Date__c FROM Order WHERE OrderNumber = :req.orderNumber LIMIT 1]; res.status = ord.Status; res.deliveryDate = ord.Delivery_Date__c; results.add(res); } return results; } public class OrderStatusRequest { @InvocableVariable(required=true description='The 8-digit order number') public String orderNumber; } public class OrderStatusResult { @InvocableVariable public String status; @InvocableVariable public Date deliveryDate; } }
