What is CRM & Salesforce?

Explain Like I'm 10: The Lemonade Stand Story

Imagine you run a small lemonade stand in your front yard. When you have only 3 customers a day, you can easily remember that neighbor Bob likes extra sugar, Alice prefers crushed ice, and Charlie only visits on Tuesdays.

Now, imagine your lemonade stand expands to 10,000 stands worldwide with millions of customers. You can’t keep all those preferences in your head or on sticky notes! You need a magical digital memory notebook that your entire team can open from anywhere to know each customer’s favorite flavor, purchase history, and complaints.

CRM stands for Customer Relationship Management. And Salesforce is the most popular, powerful digital notebook in the world!

Why Do Global Enterprises Rely on Salesforce?

Before Salesforce launched in 1999, companies spent millions of dollars purchasing physical server racks, installing expensive software CDs, and maintaining private data centers. Salesforce pioneered Cloud Computing with the slogan "No Software": all you need is a web browser and an internet connection to run an entire multinational sales, customer service, and marketing team.

Sales Cloud

Track leads, deals, pipelines, and automatically forecast quarterly company revenue.

Service Cloud

Help desks, call center telephony, ticket routing, and automated AI chat resolutions.

Marketing Cloud

Personalized automated journeys across email, SMS, push notifications, and advertising.

The Multi-Tenant Architecture & Governor Limits

Explain Like I'm 10: The Apartment Building

In an apartment building, 100 families share the same central water supply, electrical wiring, and building foundation. Each family has their own private apartment with their own locked door—nobody can peek inside their rooms.

However, if family #14 decides to leave their bathtub running 24 hours a day at maximum pressure, the water pressure for the other 99 families will plummet! To protect everyone, the building manager puts a smart valve on each faucet that allows up to 100 gallons per hour.

In Salesforce:

  • Multi-Tenancy: Thousands of companies share the same underlying servers and database instances securely.
  • Governor Limits: Rules enforced by the system that prevent one company’s poorly written code from hogging CPU, memory, or database queries.

Critical Salesforce Governor Limits Every Developer Must Know

Because resources are shared across tenants, the Salesforce Apex runtime strictly enforces these limits per synchronous transaction:

Resource / Operation Synchronous Limit Asynchronous Limit (Batch/Queueable)
Total SOQL Queries (Database Reads) 100 queries 200 queries
Total Records Retrieved by SOQL 50,000 records 50,000 records
Total DML Statements (Insert, Update, Delete) 150 statements 150 statements
Total Records Processed via DML 10,000 records 10,000 records
Maximum CPU Execution Time 10,000 ms (10 seconds) 60,000 ms (60 seconds)
Heap Size (RAM Memory Allocated) 6 MB 12 MB
Golden Rule of Apex: Never write a SOQL query or DML operation inside a for loop! Always use Collections (Lists, Sets, Maps) to bulkify your logic.

Data Model: Standard & Custom Objects

Explain Like I'm 10: Spreadsheets with Superpowers

Think of a Salesforce Object as a spreadsheet tab.
• Fields are the column headers (e.g., Name, Email, Price).
• Records are the individual rows of data (e.g., John Doe, john@example.com, $500).

Unlike a simple Excel spreadsheet, Salesforce connects different sheets together automatically. For example, a single "Company" sheet can link to 50 "Employee" rows and 10 "Invoice" rows instantly!

Standard vs. Custom Objects

  • Standard Objects: Built-in out of the box by Salesforce. Examples include Account (Companies), Contact (People working at companies), Lead (Prospective clients), and Opportunity (Deals in progress).
  • Custom Objects: Created by your administrators or developers to model unique business requirements. Their API names always end with __c (e.g., Invoice__c, Delivery_Route__c).

Object Relationships: Master-Detail vs. Lookup

Lookup Relationship (Loose Couple)

Links two objects together, but each record can exist independently.

  • Deleting the parent record does not delete child records.
  • Child records have their own independent security and ownership.
  • Example: An Account and a Contact. If you reassign an Account, the Contact can stay.
Master-Detail Relationship (Tight Couple)

Parent controls the life and death of child records.

  • Deleting the Master cascade-deletes all child records!
  • Child automatically inherits security and ownership from Master.
  • Allows Roll-Up Summary fields (SUM, MIN, MAX, COUNT of child records directly on the parent).
  • Example: An Invoice__c and its Line_Item__c rows.

Security & Data Access: The Castle Model

Explain Like I'm 10: The Medieval Castle

Salesforce security works like layers of protection guarding a royal castle:

1. Castle Drawbridge (User License & Login IP): Are you allowed to step foot on castle grounds?
2. Your Royal Job Title (Profiles & Permission Sets): Are you a royal cook or a knight? Cooks can open the kitchen (CRUD: Create, Read, Update, Delete on recipes), but only knights can touch swords.
3. The Secret Room Lock (OWD - Organization-Wide Defaults): Is the royal treasury locked by default (Private), or can everyone peek inside (Public)?
4. The King’s Perch (Role Hierarchy): The King and Generals can see everything their soldiers under them see!

The 4 Layers of Salesforce Security

Layer Mechanism What It Controls
1. Object-Level Profiles & Permission Sets Can a user Create, Read, Edit, or Delete (CRED) any records of this Object type?
2. Field-Level Field-Level Security (FLS) Can a user view or edit a specific field (e.g., Credit Card Number or Salary)?
3. Record-Level (Baseline) Organization-Wide Defaults (OWD) If you don't own the record, can you see it? (Private, Public Read Only, Public Read/Write).
4. Record-Level (Exceptions) Role Hierarchy, Sharing Rules & Manual Sharing Opens up additional access to specific managers, teams, or territories.

Declarative Automation: Salesforce Flows

Before writing a single line of code, Salesforce encourages admins to use declarative automation (clicks, not code). Salesforce Flow is the premier graphical tool that allows you to automate complex business logic visually.

Screen Flows

Interactive visual wizards with forms, questions, and buttons guiding users step-by-step through a business process.

Record-Triggered Flows

Execute automatically in the background when a record is created, updated, or deleted (replaces legacy Workflow Rules & Process Builder).

Schedule-Triggered Flows

Run on a recurring schedule (e.g., every night at midnight to check for overdue invoices).

Flow Best Practices: Fast Field Updates vs. Actions & Related Records
  • Before-Save (Fast Field Updates): Runs before the record is saved to the database. 10x faster! Use this whenever you are updating fields on the record that triggered the flow.
  • After-Save (Actions & Related Records): Runs after the record is saved. Use this when sending emails, calling external webhooks, or updating other related records.

Programmatic Apex & SOQL

When point-and-click Flows cannot handle complex calculations, massive volume aggregations, or specialized API integrations, developers use Apex. Apex is a strongly-typed, object-oriented language with syntax very similar to Java and C#.

1. Writing a Clean, Bulkified Apex Trigger

Best Practice Pattern: One Trigger Per Object delegating execution immediately to an Apex Handler class.

// File: AccountTrigger.trigger trigger AccountTrigger on Account (before insert, before update, after insert) { if (Trigger.isBefore && Trigger.isInsert) { AccountTriggerHandler.handleBeforeInsert(Trigger.new); } }
2. The Trigger Handler Class with Bulkified SOQL
// File: AccountTriggerHandler.cls public with sharing class AccountTriggerHandler { public static void handleBeforeInsert(List<Account> newAccounts) { // Collect industry names to avoid duplicate queries Set<String> industries = new Set<String>(); for (Account acc : newAccounts) { if (acc.Industry != null) { industries.add(acc.Industry); } } // Bulkified SOQL query outside any loop! Map<String, Tax_Rate__c> taxRates = new Map<String, Tax_Rate__c>(); for (Tax_Rate__c tr : [SELECT Industry__c, Rate__c FROM Tax_Rate__c WHERE Industry__c IN :industries]) { taxRates.put(tr.Industry__c, tr); } // Apply values in memory for (Account acc : newAccounts) { if (taxRates.containsKey(acc.Industry)) { acc.Default_Tax_Rate__c = taxRates.get(acc.Industry).Rate__c; } } } }

Asynchronous Apex

When you have long-running jobs, web service callouts, or need to process up to 50 million records without hitting governor limits, you run code asynchronously in the background.

Type Interface / Annotation Best Used For
@future @future(callout=true) Simple asynchronous method for third-party callouts or avoiding Mixed DML errors (Setup vs Non-Setup objects). Only accepts primitive arguments.
Batch Apex Database.Batchable<sObject> Processing massive data sets (up to 50 million records) chunked into batches of 200 records each. Features start, execute, and finish lifecycle methods.
Queueable Apex System.Queueable The modern, robust replacement for @future. Supports non-primitive objects, returns a Job ID for tracking, and allows chaining one job after another.
Schedulable Apex System.Schedulable Running Apex on a defined cron schedule (e.g., daily at 2:00 AM).

Lightning Web Components (LWC)

Lightning Web Components (LWC) is Salesforce's modern UI development framework built on top of standard Web Components (HTML5, ES6+ JavaScript, CSS3, and Shadow DOM).

Component Architecture

Every LWC consists of at least three core files in its bundle:

component.html

HTML template declaring the visual markup, layout, and data-binding expressions using {propertyName}.

component.js

JavaScript ES6 class extending LightningElement to handle user events, state, and server calls.

component.js-meta.xml

Metadata configuration exposing the component to App Builder, Record Pages, or Experience Cloud.

Key LWC Decorators
  • @api: Makes a property or method public so parent components or Lightning App Builder can pass data into it.
  • @track: Explicitly tracks deep mutations within objects and arrays to trigger reactive re-rendering.
  • @wire: Connects the component to Salesforce data and Apex methods via Lightning Data Service (LDS) reactive caching.

APIs & Integration Architecture

No enterprise system lives in isolation. Salesforce provides industry-standard integration mechanisms to exchange data with ERPs (SAP, Oracle), payment gateways (Stripe), and microservices:

REST & SOAP Apex Callouts

Outbound HTTP calls using HttpRequest and Http classes authenticated seamlessly through Named Credentials (storing secrets safely without hardcoding tokens in code).

Platform Events & CDC

Event-driven pub/sub architecture built on CometD and Apache Kafka. Change Data Capture (CDC) automatically publishes event streams whenever records are modified.
